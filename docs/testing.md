# Testing and release checks

The suite is designed to keep calculation behaviour reproducible without service credentials or network access.

## Test layers

1. **Fixture-driven unit tests** check pure calculations against hand-checked records and expected values. Generated sample-organisation data is changed through its seeded generator, not by editing generated JSON.
2. **Mocked source tests** inject `fetch` responses to check parsing, error handling and request behaviour without contacting GitHub, PagerDuty, Sentry, Prometheus or BigQuery.
3. **CLI end-to-end smoke test** invokes the built CLI for representative offline commands.
4. **Repository safeguards** include typechecking, lint, coverage thresholds, a build-size budget and a credential-pattern test.
5. **Metric sensitivity report** runs one fixed synthetic dataset over multiple covered windows and compares the revert-proxy and incident-linked CFR calculations. Its input and limits are documented in `docs/metric-scenarios.md`.

## Run the documented gate

```sh
pnpm typecheck
pnpm lint
pnpm test
pnpm build
pnpm size
pnpm e2e
pnpm eval:scenarios
```

The first six commands are the repository's CI and pre-push gates in the same order. `pnpm test` enables coverage thresholds; `pnpm e2e` uses the built output. `pnpm eval:scenarios` is an optional offline report and is not part of CI. Current results are generated by running these commands in the repository; this document does not claim that a past green run proves a later revision.
